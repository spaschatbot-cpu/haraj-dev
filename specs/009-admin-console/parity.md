# قائمة التكافؤ — اللوحة الجديدة مقابل `admin2` و`admin3`

**الحالة: مسوّدة تنتظر المالك. غير موقَّعة.**

> **⚠️ لا تُطفأ أي لوحة قديمة قبل توقيع المالك على هذه القائمة (I7، وQ4 في
> [الخارطة](../000-roadmap.md)).** الإطفاء قبل التوقيع ليس قراراً تقنياً يُتخذ
> نيابةً عنه: المالك يستعمل `admin2` يومياً، وما يعرفه عن استعمالها ليس مكتوباً
> في أي مكان في هذا المستودع.

---

## لماذا نصف هذه الوثيقة فارغ

النصف المكتوب هنا هو **ما تفعله اللوحة الجديدة**، وهو مشتقٌّ من
`apps/console/navigation.py` — السجلّ الذي يحرس الصفحات ويعرضها، فلا يمكن أن
يذكر شاشةً غير موجودة ولا أن ينسى شاشةً موجودة.

النصف الفارغ هو **ما يفعله المالك في `admin2` و`admin3`**، ولا يمكن لأحد غيره
ملؤه. لا يوجد في هذا المستودع جردٌ لتلك اللوحتين — لا شيفرتهما ولا وثيقةٌ عنهما
— وأيّ بند أكتبه في عمودهما سيكون تخميناً، وتخمينٌ في قائمةٍ يُوقَّع عليها أسوأ
من خانة فارغة: الخانة الفارغة تُسأل، والتخمين يُصدَّق.

**الطريقة المقترحة:** يفتح المالك `admin2` ويمرّ على شاشاتها شاشةً شاشة، ويكتب
في العمود الأيمن ما يفعله فيها فعلاً — لا ما تستطيع أن تفعله. الفرق بينهما هو
كل الفائدة: شاشةٌ موجودة ولا تُستعمل لا يجب أن تُبنى مرة أخرى.

## أ — ما تفعله اللوحة الجديدة اليوم

### التشغيل اليومي

| الشاشة | ما تفعله | يقابلها في القديم | ناقص؟ |
|---|---|---|---|
| الرئيسية | ما يستطيع هذا الشخص فتحه، بقائمته هو لا بلوحة أرقام | | |
| المزادات | كل مزاد بحالته وعدد مركباته، بحث بالرقم والعنوان، ترشيح بالحالة | | |
| تفاصيل المزاد | مركبات المزاد، وما ينتظر قراراً في أوّلها لا في ترتيب اللوت | | |
| مزاد جديد / تعديل مزاد | إنشاء وتعديل، والحالة تتغيّر بالخدمة لا بحقل | | |
| المركبات | بحث عبر المزادات بالماركة والطراز واللوت | | |
| تفاصيل المركبة | حالتها، والانتقالات المسموحة مشتقّة من آلة الحالات | | |
| تغيير حالة المركبة | نقلة واحدة بسبب مكتوب، وتُسجَّل | | |
| استيراد المركبات | رفع ملف، تشغيل تجريبي، وكل صف مرفوض باسمه في ملف يعمل عليه المشغّل | | |
| تصدير المركبات | نفس الملف الذي يُرفَع — ينزل ويُرفَع ثانيةً بلا تعديل ولا يغيّر صفاً | | |
| قرارات الشركاء | ما ينتظر قرار شريك، مرتّباً بطول الانتظار | | |
| العروض | كل المزايدين على المركبة، والعرض **المقبول** لا الأعلى | | |
| الترسية | ترسية على أيّ مزايد بنقرة، ونقل الترسية يلغي الفاتورة الأولى ويفكّ قفل الفائز الأول | | |
| رفض المالك | يُسجَّل «مرفوضة» لا «مسحوبة»، وتعود المركبة في مزاد لاحق | | |
| المستخدمون | بحث بالجوال والاسم والهوية | | |
| بيانات العميل / تعديله / تعديل شركته | تحقّق قبل الحفظ: قيمة حدّية تسمّي حقلها ولا تُجهض التحديث كله | | |

### المال

| الشاشة | ما تفعله | يقابلها في القديم | ناقص؟ |
|---|---|---|---|
| الفواتير | كل فاتورة بحالة **مشتقّة من دفعاتها المرحَّلة**؛ المسودّة ليست دفعة | | |
| تفاصيل الفاتورة | المبلغ والمسدَّد والمتبقّي، وكلام أودو بجانبها موسوماً بأنه كلامهم | | |
| دفتر التأمينات | العملاء الذين يملكون رصيداً، ورقم جوال كامل يفتح دفتر صاحبه مباشرةً | | |
| دفتر عميل | الدلاء والحجوزات بأسبابها والحركات. **قراءة فقط** | | |
| أفعال مالية | صفحة مستقلّة: مصادرة، تصحيح، ومنح استثناء — كلها بسبب مكتوب واسم منفّذ | | |

### التشخيص

| الشاشة | ما تفعله | يقابلها في القديم | ناقص؟ |
|---|---|---|---|
| صحة المال | ملاحظات الدفتر مع نفسه، وفروقه مع أودو، والمعلّق بلا صاحب — والملاحظة تُغلق بزوال سببها | | |
| صندوق وارد أودو | كل رسالة بحالتها، ونصّها كما وصل، وإعادة تشغيل تمرّ على المسار الآلي نفسه | | |
| ليه ما يقدرش يزايد؟ | رقم جوال ← آخر الرفضات بلقطة فلوسه **وقت الرفض** | | |

### الإدارة

| الشاشة | ما تفعله | يقابلها في القديم | ناقص؟ |
|---|---|---|---|
| سجل التدقيق | بحث بالمنفّذ والكيان والفترة، وقائمة الأفعال مشتقّة من الصفوف | | |

### يعمّ كل الشاشات

| السلوك | ما يعنيه | يقابله في القديم | ناقص؟ |
|---|---|---|---|
| صلاحية واحدة لكل صفحة | الصفّ الذي يعرضها في القائمة هو الصفّ الذي يحرسها | | |
| كل قائمة تُصدَّر | ملف `.xlsx` حقيقي يفتح في إكسل بلا تحذير، **ويحترم المرشِّح على الشاشة** | | |
| كل كتابة تُسجَّل | من فعل، وماذا كان قبلها، ولماذا | | |
| لافتة البيئة | كل صفحة تقول أي بيئة هي | | |
