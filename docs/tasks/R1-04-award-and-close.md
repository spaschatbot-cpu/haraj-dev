# R1-04 · الترسية والإغلاق

## الأعمدة
`auction_vehicles`: `winner_user_id` · `winning_bid_id` · `final_price` ·
`awarded_at` · `approval_status` · `winner_paid_at` · `payment_method` ·
`transaction_ref` · `receipt_image_path`
`bids`: `offer_status` (`pending` → `accepted` / `rejected`)

## التسلسل
```
انتهاء المزاد → قرار (قبول/رفض) → إرسال الفواتير للكل → ربط/تحرير التأمين → إشعار الفائز
```

## قواعد
1. **القبول وحده لا يُنشئ فاتورة ولا يرسل رسالة.** كلٌّ خطوة صريحة منفصلة.
2. **«إرسال الفواتير للكل» (`finalizeDecisionAuction`) هي اللحظة الوحيدة التي يرتبط
   فيها المال أو يُفكّ.** قبلها الرفض مؤقّت ولا يحرّر وديعة.
3. **الرفض يرفض كل مزايدات المركبة** ويمحو وسم الفائز — لا يرقّي التالي تلقائياً.
   الترقية قرار صريح (استبدال المزايد).
4. **سيارة التسويق: قرار الشريك أولاً** — محروسٌ في 22 موضعاً، والحارس في الخدمة
   لا في الصفحة.
5. **الترسية من أي شاشة تكتب نفس الأعمدة** — لا مسار ثانٍ للحجوزات أو غيرها.
6. **الفاتورة الملغاة لا تُعيد السيارة للقرار داخل نفس الدورة**، لكنها لا تحجبها
   في دورة جديدة.

## معايير القبول
- [ ] الترسية من admin2 وadmin_v2 والحجوزات تعطي نتيجة واحدة
- [ ] لا فاتورة تصدر قبل قرار
- [ ] التأمين يُربط ويُفكّ في لحظة إرسال الفواتير فقط
