# P1-02 · اختيار العروض والترسية

> **4,067 طلب** على `admin2/bills` — والمالك يستعملها يومياً.
> `admin2/bills/index.php` + `src/Services/BillDecisionService.php` + `BillController`.
> هنا يتحوّل العرض إلى بيع: القبول يكتب `bids.offer_status='accepted'`، وكل ما بعده
> (الفاتورة · الرسالة · قفل التأمين) يقرأ ذلك العمود.

## ما تفعله

| الإجراء | الأثر |
|---|---|
| **قبول** | `UPDATE bids SET offer_status='accepted'` — لا فاتورة ولا رسالة |
| **رفض** | كل مزايدات المركبة → `rejected`، ويُمحى وسم الفائز |
| **استبدال المزايد** | يرفض الباقي ويُبقي المختار `pending` |
| **تعديل الأسعار** | يغيّر `amount` و`amount_with_vat` معاً |
| **قائمة المزايدين** | كل العروض مرتَّبة — ومنها يُقبل غير الأعلى |
| **إنشاء جميع الفواتير** | `WHERE offer_status='accepted' AND status='active'` |
| **رسائل للفائزين** | نفس الشرط تماماً |
| **تصدير إكسل** | من استعلام الصفحة نفسه |

## الجداول

`bids` (`offer_status` · `status` · `amount` · `amount_with_vat` · `vehicle_id`) ·
`auction_vehicles` (`winner_user_id` · `final_price` · `awarded_at` · `approval_status`) ·
`invoices_odoo` · `auctions` (`vat_type` · `fees`)

## قواعد لا تُكسر

1. **القبول لا يُصدر فاتورة ولا رسالة.** الفوترة خطوة منفصلة صريحة، والإشعار ثالثة.
   دمجها أطلق فواتير أودو ورسائل فور الضغط — وهو ممنوع بقرار سير العمل.
2. **قرار الشريك يسبق قرار المالك** على سيارات التسويق: `PartnerVehicleLock` يمنع
   القبول والرفض والاستبدال حتى يُختم `partner_decided_at`.
   الحارس في `BillDecisionService` لا في الصفحة، لأن النقاط تُبلَغ بـPOST مباشر.
3. **الضريبة تُضاف عند الفوترة لا عند القبول.** `أعلى عرض` رقم خام.
4. **`vat_type` يُخزَّن كنسبة أو ككسر** — طبِّعه دائماً.
5. **السيارة تغادر الصفحة عند الفوترة**، وتبقى خارجها حتى لو أُلغيت فاتورتها —
   لكن **داخل نفس دورة المزاد فقط**.
