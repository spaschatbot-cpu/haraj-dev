# R3-01 · إنشاء الفاتورة

## متى
```
مزاد منتهٍ → عرض offer_status='accepted' وstatus='active' → «إنشاء جميع الفواتير»
```
لا فاتورة قبل قرار، ولا فاتورة تلقائية عند القبول.

## المكوّنات
`amount` (العرض الفائز) + `fees_amount` (رسوم المزاد) → `total`
ثم الضريبة عند الترحيل. `vat_type` = `15` أو `0.15` — طبِّعه.

## قواعد
1. **سيارة واحدة = فاتورة واحدة.** الحارس على `(customer, auction)` والمركبة.
   حلقة 2026-06-06 أنتجت 786 نسخة لأن `vehicle_id` وصل NULL في المرآة.
2. **الإنشاء عملية خاملة (idempotent)** — إعادة الضغط أو تشغيل الكرون لا تُنتج ثانية.
3. **المذكرة هي مرجع الدفعة في أودو**، وتكرارها يرفضه أودو. السداد الجزئي يحتاج
   «دفعة N» ملحقة، وإلا رُفضت 223 محاولة على 26 فاتورة.
4. **⚠️ جدولة أي كرون يكتب في أودو تحتاج موافقة صريحة** — كرون واحد أصدر 38 فاتورة
   غير مرغوبة (عُكست).
5. **الفرملة في `.env` ما زالت مفعّلة** من حادثة الازدواج — لا تُرفع بلا قرار.

## معايير القبول
- [ ] لا مركبة بفاتورتين ساريتين
- [ ] إعادة التشغيل لا تُنشئ شيئاً
- [ ] كل فاتورة مربوطة بمركبة عبر `vehicle_id`
