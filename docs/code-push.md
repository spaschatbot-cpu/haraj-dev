# التحديثُ الداخليّ للتطبيق (Shorebird)

**المشكلة** (المالك، ١٧ نوفمبر ٢٠٢٦): كلُّ تعديلٍ صغيرٍ في التطبيق كان يعني
إصداراً جديداً ومراجعةً عند Apple وGoogle، وذلك يأخذ أيّاماً.

**الحلّ**: [Shorebird](https://shorebird.dev) — يرسل تعديلَ كود دارت إلى
التطبيق المثبَّت مباشرةً («ترقيع» / patch)، بلا رقم إصدارٍ جديد ولا مراجعة.
وهو مسموحٌ في المتجرين: يغيّر الكودَ المفسَّر لا الأصليّ.

## ما يصل ترقيعاً وما لا يصل

| يصل ترقيعاً (`mobile-patch`) | يحتاج إصداراً (`mobile-release`) |
|---|---|
| أيُّ تعديلٍ في `mobile/lib/` — شاشة، نصّ، منطق، لون | مكتبةٌ جديدة فيها كودٌ أصليّ (أغلبُ إضافات pub.dev التي تلمس الجهاز) |
| صورٌ وخطوطٌ في `assets/` | إذنٌ جديد (كاميرا، موقع…) |
| | الأيقونة وشاشة الإقلاع والاسم |
| | ترقيةُ Flutter |

وShorebird نفسُه يرفض الترقيعَ حين يجد فرقاً أصليّاً ويقول السبب — فلا يُرسَل
ترقيعٌ يكسر التطبيق.

> **وما لا يحتاج حتى ترقيعاً**: لونُ التطبيق وإضاءتُه من «مظهر التطبيق» في
> اللوحة (`/api/v1/appearance/`)، وكلُّ ما يأتي من الخادم.

## مرّةً واحدة

1. **حساب** على [console.shorebird.dev](https://console.shorebird.dev) (فيه
   خطّةٌ مجانيّة بحدٍّ شهريٍّ لتثبيت الترقيعات).
2. **مفتاحٌ لـGitHub**: المنظّمة ← Settings ← **Service accounts** ←
   Create service account (الاسم `GitHub Actions`)، والدور **App Manager**
   (أوّلُ تشغيلٍ ينشئ التطبيق) ← API keys ← **Create key**. يُنسخ مرّةً واحدة.
3. **في GitHub**: Settings ← Secrets and variables ← Actions ← New repository
   secret: الاسم `SHOREBIRD_TOKEN` والقيمة المفتاح.
   وإن كان للحساب أكثرُ من منظّمة: متغيّر (Variables) `SHOREBIRD_ORG_ID`.
4. أسرارُ Apple الأربعة لـTestFlight — `docs/testflight.md`.

## الإصدار — `mobile-release`

Actions ← **mobile-release** ← Run workflow:

- **أوّلُ تشغيل** يُنشئ التطبيق في Shorebird ويدفع `mobile/shorebird.yaml` إلى
  main وحده (commit من `github-actions[bot]`). **لا يُعاد بـ`--force`**: ذلك
  يُنشئ تطبيقاتٍ جديدة فتنقطع الترقيعاتُ عن كلّ نسخةٍ مثبَّتة.
- iOS ← TestFlight. أندرويد ← APK في Artifacts صفحةِ الـrun (نكهة staging).
- **الإصدارُ في Shorebird = `الاسم+رقم السير`**، مثل `1.0.0+3`، ويظهر في
  ملخّص الـrun. به يُستهدَف الترقيع.

## الترقيع — `mobile-patch`

بعد الدفع إلى main: Actions ← **mobile-patch** ← Run workflow. المنصّات، و
الإصدار (`latest` = آخرُ إصدار). نحو ١٠–١٥ دقيقة.

**ويصل هكذا**: التطبيقُ يسأل Shorebird عند فتحه، فينزّل الترقيعَ في الخلفيّة،
**ويسري في الفتحة التالية**. فمن يريد رؤيته الآن: يغلق التطبيقَ تماماً ويفتحه،
ثمّ يكرّر.

## ما يجب ألّا يُنسى

- **بناءٌ من `flutter build` لا يقبل ترقيعاً** — حزمةُ `mobile-apk` للتجربة
  السريعة فقط، والموزَّعةُ هي حزمةُ `mobile-release`.
- **Flutter 3.44.9** في السيرين، لا 3.44.8: Shorebird يقول إن إصدارات iOS
  المبنيّة بـ3.44.0–3.44.8 قد تنهار حين يُثبَّت عليها ترقيع.
- تعريفاتُ دارت (`--dart-define`) في الترقيع **حرفاً بحرف** كما في الإصدار.
  تغييرُ أحدها في سيرٍ يلزم تغييرَه في الآخر.
- 🟡 أندرويد موقَّعٌ بمفتاح تصحيح الماكينة (لا مفتاحَ إصدارٍ بعد): إصدارٌ
  جديد لا يُثبَّت فوق القديم إلا بعد حذفه. والترقيعُ لا يتأثّر. ولا Google
  Play قبل مفتاح إصدار.
- النكهات: `shorebird init` يُنشئ تطبيقاً لكلّ نكهةٍ أندرويد (`dev`
  و`staging` و`prod`)، وiOS — بلا نكهات — يأخذ `app_id` الأعلى في الملفّ.
  فترقيعُ iOS يظهر في الكونسول تحت ذلك التطبيق.
