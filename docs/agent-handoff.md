## القواعد التي تُحاسَب عليها

- **تاسك واحد في المرة.** لا تدمج تاسكين ولو بديا صغيرين (المادة ٦-٢).
- **لا تدّعِ نتيجة لم تشاهدها** (المادة ٦-٤). لو لم تُشغَّل الاختبارات، قل ذلك.
- **أثبت العطل بالتشغيل قبل إصلاحه.** اكتب إثباتاً مؤقّتاً، شغّله، انسخ رسالة
  الفشل الحقيقية، ثم أصلح. عطلٌ «قرأتَه» ليس عطلاً رأيتَه.
- **واختبارك يجب أن يفشل بدون تغييرك، وأثبت ذلك:**
  `git stash push -q <الملفات>` ثم شغّل، ثم `git stash pop -q`.
  اختبارٌ لا يفشل بدون ما يحرسه ليس حارساً.
- **لا شيء يكتب في الدفتر إلا `apps.money.services.post`.** بلا استثناء.
- **العملة `Decimal(14,2)`.** ممنوع `float` في أي مسار مالي، ولو في تقرير.
- **القيد في السكيمة قبل القيد في الكود** (المادة ٣-٣). ما يمكن أن يكون
  `UNIQUE` أو `CHECK` يُكتب هناك، والكود يعطي الرسالة المفهومة.
- **التعليق يشرح السبب لا الفعل** (المادة ٤-٦). تعليقٌ يعيد صياغة سطره يُحذف.

## معيار «منتهٍ» — الستّة، لا خمسة

  1. اختبارٌ يفشل بدون التغيير، **ومُثبَتٌ بإفشاله**.
  2. الحزمة كاملة خضراء على PostgreSQL:
         cd backend && uv run pytest -q
  3. `verify_ledger()` نظيف بعد كل سيناريو يمسّ المال.
  4. كل الحرّاس خُضر:
         for f in ops/checks/*.py; do backend/.venv/Scripts/python.exe "$f" || echo "FAIL $f"; done
  5. ruff نظيف:
         cd backend && uv run ruff format . && uv run ruff check .
  6. `tasks.md` محدَّثٌ بما نُفِّذ **وبما لم يُنفَّذ ولماذا** (المادة ٦-٦)،
     و`docs/v1-rebuild-tasks-map.md` و`docs/work-order.md` تعكسان الحالة.

## الرفع

    git checkout -b <الفيز>/<التاسك>-<وصف-قصير>     # مثال: 002/HR-08-card-for-deposits
    git add <الملفات>
    git commit                                       # الرسالة بالعربية، تقول لماذا لا ماذا
    git push -u origin <الفرع>
    git checkout main && git pull
    git merge --no-ff <الفرع>
    git push origin main

**رسالة الكوميت تشرح القرار وسببه، لا قائمة الملفات.** اقرأ آخر خمس رسائل في
`git log` قبل أن تكتب أولاك — هي المعيار.

## ما تتوقّف عنده وتسأل، ولا تقرّره بنفسك

- **spec يخالف الدستور** — توقّف واسأل، ولا تصلح الدستور (المادة ٦-٥).
- **تغيير أي إعداد أو مفتاح تكامل** يحتاج إذناً صريحاً لكل حالة (المادة ٥-٤).
- **جدولة أي مهمة تكتب في نظام مالي خارجي** تحتاج موافقة **قبل** جدولتها
  (المادة ٥-٢ — كرونٌ واحد في v1 أصدر 38 فاتورة غير مقصودة).
- **أي قرار في جدول «🔒 قرارات» في `work-order.md`.** تلك قرارات مالك لا شغل.

## فخّان وقعتُ فيهما، فلا تقع فيهما

1. **`deposit_insurance` بلا قيد مضاعفات — عمداً.** الفيز 004 يعيد بناء تاريخ
   v1، وفيه وديعةٌ بريال واحد. دفترٌ لا يستطيع التعبير عمّا حدث لا يمكن
   مطابقته بما حدث. **لا تُضِف القيد هناك** (HR-03).
2. **شرطان على علاقةٍ متعدّدة في `filter()` واحد يُطبَّقان على نفس الصفّ.**
   معاملةٌ لها قيدان — قيدُ العميل وقيدُ حساب النظام — فـ`filter(entries__owner=…,
   entries__account__kind=…)` يسأل عن قيدٍ واحد يجمعهما ولا وجود له. اربط
   `.filter()` مرتين (HR-10).

## للمشرف — ما تفحصه في شغل الوكيل

قبل قبول أي تاسك منه، اسأل هذه الخمسة. كلٌّ منها أمسك خطأً حقيقياً في هذا
المستودع:

| # | الفحص | لماذا |
|---|---|---|
| 1 | **هل الاختبار يفشل بدون التغيير؟** اطلب الدليل، لا الادّعاء | `test_an_anonymous_visitor_is_sent_to_sign_in` كان أخضر طوال فيز كامل على تحويلٍ إلى **404** — اسمه ادّعى ما لم يفحصه |
| 2 | **هل العطل شوهد بالتشغيل أم قُرئ؟** | HR-10 «يبدو محروساً» بمفتاح الخمول — والتشغيل أظهر الرصيد يتضاعف إلى 20,000 |
| 3 | **هل يستعمل مبالغ إنتاجية؟** | تجهيزةٌ تموّل بخمسة أضعاف الوديعة أخفت عطلاً منع فوترة الفائزين كلها |
| 4 | **هل القيد في السكيمة أم في بايثون وحدها؟** | قيمةٌ افتراضية على `Invoice.source` كانت ستكون الفخّ نفسه |
| 5 | **هل قال ما لم يُنفَّذ؟** | تاسكٌ «منتهٍ» بلا قائمة نواقص إمّا كامل وإمّا غير مقروء |

**وراجع بنفسك ما يمسّ `apps/money`** مهما كان كاتبه — خطة الفريق §3.
