# مقارنة: صفحة **سيارات المزاد** (`/auctions/{id}/vehicles`) — v1 ⇄ v2

> ⚠️ **نطاقُ هذه الوثيقة:** صفحةُ `‏/admin_v2/auctions/{id}/vehicles` في v1
> (`manageVehicles` + `manage_vehicles.php`) — **وليست** صفحةَ «إدارة المزاد +
> سياراته» (`/auctions/{id}/manage`, `AuctionController::manage` +
> `Views/Admin/auctions/manage.php`)، وهي صفحةٌ أخرى محورُها الصورُ وصورةُ العرض.
> كُتبت هذه بالخطأ تحت اسم تلك، والتصحيحُ هنا حتى لا يُبنى على المرجع الخطأ.

مصدر v1: `applicationtest/src/Controllers/Admin/AuctionController.php` + `src/Views/Admin/auctions/manage_vehicles.php` (المسار `/admin_v2/auctions/{id}/vehicles`).
مصدر v2: `apps/console/auctions.py::auction_detail` + `templates/console/auction_detail.html` (المسار `/console/auctions/{pk}/`)، بعد دمج تحويلها إلى كروت (T880).

> **الخلاصة التنفيذية:** v2 أسلم بنيةً (كاتبٌ وحيد للحالة، رفعُ صورٍ مُعقَّم بمصغّرات، تدقيقٌ لكل فعل، تخصيصُ أعمدةٍ لكل مستخدم). **لكن تحويلها إلى كروت كسر/أيتم وظائفَ v1 الأساسية:** الجدول ذو ١٧ عموداً صار كارتاً بـ٦ حقول، وضاعت خاناتُ بحث الأعمدة، وتخصيصُ الأعمدة، والتحديدُ الجماعي، وأزرارُ النقل/الحذف على الصف (مودالاتها موجودة بلا مُشغِّلات). التفصيل في القسم ٧.

## ١) طريقة العمل والاستخدام

| | v1 | v2 |
|---|---|---|
| الدور والصلاحية | `owner/manager/admin/supervisor` + `auctions_manage` | `AUCTIONS_MANAGE` (`can_manage`) |
| الإطار | «الخطوة ٢» من معالج إضافة السيارات | صفحة تفاصيل المزاد (والخطوة ٢ بعد الإنشاء) |
| إضافة مركبة | مودال نموذج (client-side يملؤه من JSON مُضمّن) | مودال AJAX (`fetch` لـ`vehicle-new?auction={pk}&modal=1`)، حفظ يعيد 204 |
| تعديل المزاد | — | مودال محلّي، **هويّة فقط** (رقم/عنوان/موقع)؛ الموعد/التأمين نوافذ أخرى |
| الاستيراد | منطقة سحب ملف `csv_file` | زر «رفع إكسل» (`&lt;label&gt;` يلفّ input، رفع فوري) |
| ما بعد الحفظ | يبقى في الصفحة (flash) | 204 → reload، أو توجيه لصفحة المزاد |

**جوهر الفرق:** v1 يحمّل كل الصفوف في DOM ويعمل client-side (فلاتر/بحث/ترقيم في المتصفّح)؛ v2 يرشّح ويرقّم **على الخادم** (`vehicle_filters.apply` + `_page`, 25/صفحة).

## ٢) الداتا المعروضة

**v1 — جدول بـ١٨ عموداً:** # + تحديد · رقم الموقف (`lot_number`) · اسم السيارة · سنة الصنع · رقم الشاصي · رقم المطالبة · رقم اللوحة · اللون · شركة التأمين · العداد · حالة المركبة (ملوّنة) · حالة المحرك* · نوع الوقود* · المفاتيح* · الصور (عدّاد) · الحالة (منسدلة) · التسويق (زر) · الإجراءات. (* مخفية `mv-hide-col`).

**v2 — كارت بـ٦ حقول ظاهرة:** صورة الغلاف + شارة عدد الصور · الماركة+الموديل · حبّة الحالة · زر التسويق · شرائح (لوت · لوحة · شاصي · سنة). **باقي أعمدة v1 (المطالبة، اللون، التأمين، العداد، الحالة الفنية، المحرك، المفاتيح، الوقود، ناقل الحركة، المالك) لا تظهر على الكارت** — رغم أنها معرّفة في `columns.py` (١٩ عموداً) ومُمرَّرة، لكنها لم تُرسَم.

**الملخّص العلويّ:**
- v1: اسم المزاد · البدء · النهاية + تبويبات عدّادات (حالة/صور/تسويق) تُحسب **في المتصفّح**.
- v2: بطاقة ملخّص (رقم · عنوان · شارات حالة/مرحلة · بدء · نهاية · موقع · تأمين · رسوم · تذكير SMS) + **٤ كروت إحصاء** (إجمالي · معروضة الآن · تنتظر قراراً · رست) من `view.cars`، وعدّادات الفلاتر تُحسب **على الخادم** قبل الترشيح.

## ٣) طريقة العرض

| | v1 | v2 |
|---|---|---|
| الشكل | **جدول** (زجاجي ذهبي) | **كروت** (`veh-grid`/`veh-card`) |
| الترتيب | `id DESC` (الأحدث) | `urgency` ثم `lot` (ما يحتاج قراراً أولاً) |
| الفلاتر | client-side على DOM كامل: حالة/صور/تسويق (handlers مستقلة) | server-side: تبويبات حالة/صور/تسويق بعدّاداتها، تتراكب AND |
| البحث | صفّ فلترٍ **لكل عمود** (`vehColFilter`) | خانة **موحّدة** `q` (اسم/لوحة/شاصي/لوت) + تطبيع عربي |
| الترقيم | كل الصفوف في DOM، عرض 100/250/500/الكل | خادميّ حقيقيّ، 25/صفحة (حدّ `MAX_PAGE_SIZE`) |
| تخصيص الأعمدة | — (أعمدة ثابتة، بعضها مخفيّ بـclass) | `ColumnLayout` لكل مستخدم + سحب لإعادة الترتيب |
| التمييز البصري | حالة فنية ملوّنة (أخضر/أحمر/أصفر)، وميض `?focus=ID` | نغمات `data-tone`، خلفية «لا صورة» عند الفشل، lazy load |
| حاويات خاصة | مزادان `1000/1005` يعرضان حالة `later/coming` عبر المزادات (`data-aid`) | لا نظير — الحالةُ لافتةٌ (`showcase`) منفصلة عن الحالة |

## ٤) الصور

| | v1 | v2 |
|---|---|---|
| الحقل | `vehicle_images[]` (مع النموذج) و`images[]` (المعرض) | `images` (multiple) في صفحة المعرض |
| الأنواع | jpg/jpeg/png/webp (بالامتداد أو `image/*`) | JPEG/PNG/WEBP **بالمحتوى** (GIF/SVG مرفوضان) |
| الحدّ | — (بلا حدّ عدد صريح) | ٢٠ صورة/رفعة |
| التخزين | مختلط: **ملفّات** (`uploads/vehicles/name`) و**BLOB** في `image_blob` + جدول قديم `car_images` | **ملفّات** باسمٍ مولَّد (uuid)، لا يُستعمل اسم الرافع |
| الأمان | فحص mime سطحيّ | قراءةُ رأسٍ كسولة، رفضُ ما ليس صورة، فحصُ الأبعاد **قبل** `load` (قنبلة الضغط)، إعادةُ ترميز (إسقاط EXIF/سكربت) |
| المصغّرات | تُولَّد **عند الطلب** بـGD وتُكاش (`?w=`) | تُولَّد **كلّها في نفس النداء** (`thumbnail`+`preview`, HR-12)، لا إشارات post_save |
| العرض | بثّ blob (`/vehicle-image/{id}?w=`) أو ملف؛ دمجُ جدولين قديم/جديد | `shot.preview.url` مع fallback؛ معرضٌ مرتّبٌ (غلاف أولاً) |
| الغلاف | `is_primary=1` (BLOB) + `display_image` نصّاً | قيد `one_cover_image_per_vehicle`، أول صورة غلافٌ تلقائيّاً |
| الأفعال | رفع/حذف (حسب المصدر) | رفع/حذف (لا يمسّ القرص، يرقّي التالية)/تعيين غلاف — كلها بتدقيق وسبب، ومرشّحة على المركبة |

**v2 أسلم بوضوح:** لا BLOB في القاعدة، لا اسمَ رافعٍ في المسار، تعقيمٌ كامل، مصغّراتٌ محسوبة مرّة.

## ٥) رفع الداتا (الاستيراد والإضافة اليدوية)

**الاستيراد — المنطق متطابقٌ جوهرياً (نُقل حرفياً):** كلاهما: كشفُ ترويسة + أسماءٌ بديلة عربية/إنجليزية · قارئٌ بلا ترويسة (positional) · **مباع (فاتورة نشِطة) يُرفَض** · **غير مباع يُنقَل** (مسحُ مزايدات، تصفيرُ فوز) · تكرارٌ داخل المزاد يُحدَّث · توليدُ لوت تلقائيّ · ملخّصٌ (جديدة/محدّثة/منقولة/مرفوضة).
- الفروق: v1 دفعة ٧٥ + `AUC-{id}-{seq}` لوت؛ v2 حدّ ٥MiB + محرّك `import_vehicles(default_auction)` + تدقيقٌ لكل سيارة + تقريرُ مرفوضاتٍ كشيت. v2 «سولد» = `money.Invoice` غير ملغاة؛ v1 = `invoices_odoo`.

**الإضافة اليدوية:**
- v1 (`addVehicle`): brand/model مطلوبان + Plate مطلوب، وحقولٌ كثيرة (mvpi, doors, weight, inspection_days, preview_site, starting_price, overview, auto_bid, bidamount…) + صور مع النموذج + `settings_override`.
- v2 (`VehicleForm`): ٢٠ حقلاً (auction/lot/make/model/year/colour/vin/plate/plate_type/odometer/transmission/fuel/condition/owner/reserve/claim/insurance/runs/keys/marketing) · **الحالة والترسية ليست حقولاً** · `marketing` منسدلة · تفرّد `(auction,lot)` · `reason` اختياريّ · ختمُ تحرّرٍ متزامن (`row_stamp`).
- **v2 ينقص حقولاً يعرضها v1** (mvpi/الأبواب/الوزن/أيام الفحص/الوصف/المدينة/التفعيل) — بعضها «لا يُستورَد بعد» في v2.

## ٧) ⚠️ ما كسره تحويلُ v2 إلى كروت (يتيمٌ/مفقود — يحتاج إصلاحاً)

الـ`view` ما زال يمرّر سياقَ الجدول القديم، لكن قالب الكروت لا يرسمه:

1. **تخصيص الأعمدة معطّل**: `columns_layout` مُمرَّر لكن `_columns.html` غير مُضمَّن، والسكربت يستهدف `table [data-col]` غير موجود.
2. **خاناتُ بحث الأعمدة الثماني ضاعت**: `SEARCH_FIELDS`/`search_by_col` تُحسب وتُمرَّر، لكن لا تُرسَم (بقي البحث الموحّد `q` فقط). القالب نفسه يقول إنها «انتقلت لرأس الجدول» — ورأسُ الجدول لم يعد موجوداً.
3. **مودالا النقل والحذف بلا مُشغِّلات**: `data-row-move-modal`/`data-row-delete-modal` مرسومان، لكن أزرار `[data-row-move]`/`[data-row-delete]` غير موجودة على الكروت — فلا نقلَ ولا حذفَ لسيارةٍ مفردة من الواجهة.
4. **التحديد الجماعي والشريط المجمّع غابا**: لا خاناتِ اختيار ولا `bulkbar` — فأفعالُ `vehicle_bulk` الجماعية (حالة/نقل/حذف/تسويق) سليمةٌ في الخلفية بلا واجهةٍ تستدعيها.
5. **١١ عموداً من بيانات السيارة لم تعد تظهر** (القسم ٢).
6. **ثوابت `COLUMNS`/`ROW_ICONS`/`ACTIONS` في `auctions.py`** تخصّ قائمة المزادات لا هذه الصفحة — تشويشٌ قائم.

**الفعّال حالياً على الكارت:** الملخّص · ٤ عدّادات · تبويبات ٣ فلاتر · بحثٌ موحّد · ترقيم · ولكل سيارة: صورة/عدّاد · حالة · تبديل تسويق · شرائح · أزرار (صور/تعديل‑مودال/إظهار‑إخفاء).

**التوصية:** إمّا إعادةُ خاناتِ التحديد وأزرارِ النقل/الحذف وبحثِ الأعمدة وتخصيصِها إلى تخطيط الكروت، أو حذفُ الكود اليتيم صراحةً إن كان القرار هجرَ تلك الوظائف — فالوضع الحاليّ **نصفُ تحويل**: منطقٌ خلفيٌّ كامل بلا واجهةٍ له.
