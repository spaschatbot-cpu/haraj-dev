# TASK 02: شاشة تشخيص أهلية المزايدة (`/bid-eligibility`)

## ١. الشاشة والمسار
- مسار الشاشة: `/admin_v2/bid-eligibility`
- الصلاحية المطلوبة: `wallets_manage` أو `manage_users`.

---

## ٢. الحقول والمدخلات والنتائج
- **حقل الإدخال:** بحث برقم الجوال، رقم الهوية، أو معرف العميل.
- **بطاقة التحليل التشخيصي:**
  - حالة الحساب (نشط أم محظور).
  - حالة اكتمال الملف الشخصي ورقم الهوية والسجل الضريبي.
  - جدول تفصيل الودائع: عدد وقيمة الودائع الحرة `free`، المحجوزة لمزاد `held`، المرهونة لمستحق `locked`، والمستردة.
  - قائمة الفواتير غير المسددة المرتبطة بالعميل في Odoo وقيمتها.
  - عدد طلبات الاسترداد المعلقة التي تحجب المزايدة.
  - **النتيجة النهائية الصريحة بالعربي:**
    - حالة خضراء: `✓ العميل مؤهل للمزايدة فوراً ولديه وديعة حرة`.
    - حالة حمراء: يحدد سبب المنع الصريح (مثل: `ممنوع: توجد فاتورة غير مسددة رقم INV/2026/088 بقيمة 38,000 ر.س ترهن التأمين`).

---

## ٣. المشاكل الحقيقية السابقة
- اتصال العميل الغاضب بالدعم الفني قائلاً: "أنا دافع تأمين والموقع يرفض مزايدتي!"، وكان موظف الدعم يعجز عن معرفة سبب الرفض لأن الرفض يحدث في كود عميق داخل السيرفر.

---

## ٤. الشروط والقيود الإلزامية
1. **تشخيص محاكاة قراءة فقط (Read-Only Simulation):** تشغيل نفس شروط بوابة المزايدة العشرة بالترتيب دون حجز أي وديعة ودون كتابة أي شيء في قاعدة البيانات.
2. **إظهار الخطوة المانعة بدقة:** إذا كان سبب المنع اكتمال الهوية، أو رهن دين، أو طلب استرداد قيد التحويل، يجب توضيح ذلك بوضوح للموظف ليجيب العميل في ثوانٍ.
