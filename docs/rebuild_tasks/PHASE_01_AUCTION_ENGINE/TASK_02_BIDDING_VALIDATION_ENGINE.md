# TASK 02: محرك فحص واعتماد المزايدة (Bidding Validation Engine)

## ١. الهدف ونطاق المهمة
بناء البوابة المركزية الوحيدة لاستقبال وفحص المزايدات (Single Bid Entry Point). المزاد في منصة حراج واحد هو مزاد مغلق (Sealed-bid)، ولكل عميل مزايدة واحدة فقط لكل سيارة يقوم بتعديلها حتى نهاية المزاد.

---

## ٢. الأهمية ومعدل الاستخدام
- **الأهمية:** 🔴 حرجة جداً (Financial & Core Traffic) — قلب النظام التجاري.
- **معدل الاستخدام:** آلاف الطلبات المتزامنة أثناء ذروة ساعات إغلاق المزاد.

---

## ٣. الشروط العشرة الإلزامية للمزايدة (Validation Pipeline)

تُفحص هذه الشروط تسلسلياً بالترتيب، وأول شرط يفشل يُسقط الطلب فوراً برمز الرفض المخصص:

```
الطلب الوارد (user_id, vehicle_id, auction_id, amount, confirm_lower)
   │
   ├─► [١] التحقق من جلسة العميل مسجلة ونشطة          ──► فشل: 401 NOT_LOGGED_IN
   ├─► [٢] اكتمال الملف الشخصي (الاسم، الجوال، الهوية) ──► فشل: PROFILE_INCOMPLETE
   ├─► [٣] اكتمال ملف الشركة (السجل، الضريبي، العنوان)  ──► فشل: COMPANY_TAX_INCOMPLETE
   ├─► [٤] التحقق من وجود السيارة وصلاحيتها للمزاد     ──► فشل: VEHICLE_REQUIRED
   ├─► [٥] المزاد نشط والوقت الحالي < end_time        ──► فشل: AUCTION_NOT_LIVE
   ├─► [٦] حالة السيارة نشطة وقابلة للمزايدة           ──► فشل: VEHICLE_NOT_LIVE
   ├─► [٧] السيارة غير مرساة مسبقاً لمشترٍ آخر         ──► فشل: VEHICLE_AWARDED
   ├─► [٨] المبلغ المدخل ≥ سعر الافتتاح (starting_price)──► فشل: BELOW_FLOOR
   ├─► [٩] حجز وديعة تأمين مؤهلة (10,000 ريال متاح)   ──► فشل: NO_FREE_INSURANCE / PENDING_REFUND_BLOCKS_BID
   └─► [١٠] فحص خفض السعر وتأكيد العميل الصريح         ──► فشل: 409 LOWER_NEEDS_CONFIRM
```

---

## ٤. المنطق التفصيلي للخطوة رقم [٩] (حجز التأمين للمزاد)

1. **تشغيل محرك رهن المستحقات أولاً:**
   - فحص هل العميل عليه فواتير غير مسددة في مزادات سابقة. إن وُجدت، يتم رهن ودائعه المتاحة فوراً لمنع المزايدة بمال مدين.
2. **فحص الوديعة المحجوزة الحالية لنفس المزاد:**
   - إذا كان لدى العميل وديعة بحالة `held` مرتبطة بالفعل بهذا الـ `auction_id`، يُسمح له بالمزايدة مباشرة (إعادة استخدام الوديعة لنفس المزاد).
   - **قاعدة ذهبية:** الوديعة الواحدة (10,000 ر.س) تغطي المزاد بالكامل، وتسمح للعميل بالمزايدة على أي عدد من السيارات داخل نفس المزاد.
3. **فحص طلبات الاسترداد المعلقة:**
   - إذا كان للعميل طلبات استرداد في Odoo في حالة `draft` أو `pending`:
     - يتم إلغاء مسودات الاسترداد القديمة تلقائياً إذا رغب في المزايدة.
     - إذا كانت كل الودائع مشغولة بطلبات استرداد قيد التحويل البنكي، يُرفض الطلب برمز: `PENDING_REFUND_BLOCKS_BID`.
4. **حجز وديعة حرة جديدة:**
   - اختيار أقدم وديعة بحالة `free` بقيمة 10,000 ر.س.
   - حجز الصف عبر قفل تشاؤمي (`SELECT ... FOR UPDATE`).
   - تحويل حالتها إلى `held` وربطها بالـ `auction_id`.
   - في حال عدم وجود أي وديعة حرة، يُرفض الطلب برمز: `NO_FREE_INSURANCE`.

## ٥. الجداول والأعمدة في قاعدة البيانات

### جدول المزايدات `bids`:
- `id` (int, PK)
- `user_id` (int, FK -> userss.id, INDEX)
- `auction_id` (int, FK -> auctions.id, INDEX)
- `vehicle_id` (int, FK -> auction_vehicles.id, INDEX)
- `amount` (decimal 12,2, NOT NULL) — قيمة العرض المقدم
- `amount_with_vat` (decimal 12,2) — القيمة شاملة ضريبة 15%
- `status` (varchar 50, DEFAULT 'active') — `active`, `not_active`, `deleted`
- `offer_status` (varchar 50, DEFAULT 'pending') — `pending`, `accepted`, `rejected`
- `created_at` (datetime)
- **قيد التفرّد الإلزامي:** `UNIQUE KEY uk_user_vehicle_auction (user_id, vehicle_id, auction_id)` — لكل عميل مزايدة واحدة فقط على نفس السيارة داخل نفس المزاد!

## ٦. الفخاخ التقنية السابقة (Gotchas to Avoid)
1. **تعدد مسارات المزايدة (6 Paths in Frontend):**
   - في النظام القديم: وُجدت 6 نقاط إرسال للمزايدة في واجهات المستخدم (سريعة، عادية، مودال، موبايل)، وأي تعديل في شروط المنع كان يفوت باقي المسارات.
   - **الحل:** مسار API موحد تماماً `POST /api/v1/bids` تخضع له جميع الواجهات.
2. **سباق التزامن عند إرسال مزايدتين في نفس اللحظة (Race Condition):**
   - العميل ينقر زر المزايدة مرتين في نفس الجزء من الثانية فيتم خصم وديعتين.
   - **الحل:** المعاملة بالكامل داخل `DB Transaction` مع `FOR UPDATE` على صفوف الودائع، وقيد `UNIQUE` يمنع إنشاء صفين مزايدة لنفس العميل على نفس المركبة.

## ٧. معايير القبول والاختبار
- [ ] رفض قاطع لأي مزايدة يقل سعرها عن سعر افتتاح السيارة برمز `BELOW_FLOOR`.
- [ ] رفض المزايدة فوراً إذا كان وقت المزاد منتهياً برمز `AUCTION_NOT_LIVE`.
- [ ] حجز وديعة واحدة فقط للعميل لكل مزاد مهما كان عدد السيارات التي زايد عليها.
- [ ] منع المزايد من وضع عرضين متوازيين لنفس السيارة (التعديل هو الخيار الوحيد).
