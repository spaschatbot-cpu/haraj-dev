## 4. التقنيات المعتمدة (حديثة ومثبَّتة النسخ)

القرار في خريطة الطريق (Django 5.2 LTS · DRF · PostgreSQL 17 · Celery + Redis ·
Flutter) يبقى. هذه تفاصيله وإضافاته — كل نسخة تُثبَّت في lock file، لا `latest`:

### الخلفية

| الطبقة | الاختيار | لماذا |
|---|---|---|
| Python | 3.13 + **uv** | إدارة حزم وبيئات أسرع وحتمية |
| API | DRF + **drf-spectacular** | OpenAPI 3.1 مولَّد من الكود — هو العقد مع Flutter |
| المهام | Celery 5 + Redis 7 | مع قفل نسخة واحدة لكل مهمة (المادة ٥-١) |
| المزايدة الحية | **SSE أولاً**، وChannels إن ثبتت الحاجة | SSE أبسط تشغيلاً؛ يُقرَّر نهائياً في plan.md للفيز 006 |
| الإعدادات | django-environ | أسرار خارج الكود، `.env.example` هو التوثيق |
| السجلات | **structlog** + Sentry | سجلات مهيكلة JSON من اليوم الأول |
| الاختبار | pytest + pytest-django + factory_boy + pytest-xdist | اختبارات المال على Postgres بإعدادات الإنتاج (المادة ٤-٢) |
| الجودة | **ruff** (lint + format) + **mypy** strict على `apps/money` + pre-commit | |
| CI/CD | GitHub Actions: lint ← mypy ← pytest على Postgres 17 ← build | لا دمج بغير أخضر |

### التطبيق (Flutter)

| الطبقة | الاختيار |
|---|---|
| الحالة | Riverpod (مع code generation) |
| التنقل | go_router |
| الشبكة | dio + **عميل مولَّد من مخطط OpenAPI** — ممنوع كتابة الموديلات يدوياً |
| النماذج | freezed + json_serializable |
| تخزين محلي | drift (SQLite) للكاش، flutter_secure_storage للتوكنات |
| الإشعارات | FCM |
| العربية | RTL وflutter_localizations من أول commit (T703) |
| الاختبار | unit + widget + golden tests، وintegration على مسار المزايدة |

### ويب العميل (الفيز 011)

| الطبقة | الاختيار |
|---|---|
| الإطار | **Next.js** (App Router) + TypeScript صارم |
| التنسيق | Tailwind، وRTL من أول commit |
| الشبكة | **عميل مولَّد من نفس مخطط OpenAPI** — لا نموذج مكتوب يدوياً |
| الحالة | TanStack Query للخادم، وحالة محلية بلا مكتبة إلا عند الحاجة |
| الجلسة | كوكيز `HttpOnly` — **ممنوع أي رمز في `localStorage`** |
| المزايدة الحية | SSE، نفس القناة التي يقرّرها `plan.md` للفيز 006 |
| الاختبار | Playwright للمسارات، ولقطات على ثلاثة مقاسات |

**لماذا Next وليس Flutter Web:** صفحات المركبات قناة استقطاب — الناس تبحث عن
«كامري 2022 مزاد». Flutter Web يرسم canvas بلا نص يُفهرَس، ويحمّل ميجابايتات
قبل أول بكسل.

**لماذا ليس Django templates كاللوحة:** الويب يجب أن يستهلك **العقد نفسه**
الذي يستهلكه التطبيق. لو رُسم في Django لاستدعى `services` مباشرة، فتصير كل
قاعدة عمل مُختبَرة في مكانين — وهو الباب الذي أغلقناه في الفيز 006.

### لوحة الإدارة

Django templates + **HTMX + Alpine.js + Tailwind**: تفاعلية حديثة بلا SPA ولا
build معقّد — تناسب «لوحة ويب داخل نفس مشروع Django» وتُبقي الصلاحيات في مكان
واحد. جمهورها موظفون مسجَّلون، فلا يعنيها السيو ولا وزن الحزمة.

## 5. المعمارية النظيفة (Clean Architecture)

### الخلفية — أربع طبقات، الاعتماد للداخل فقط

```
api/ (views, serializers)     ← حافة رقيقة: تحقّق شكلي، استدعاء خدمة، ردّ
services.py                   ← قواعد العمل كلها (المادة ٤-٤) — الطبقة الوحيدة التي تكتب
selectors.py                  ← قراءات معقّدة، بلا آثار جانبية
models.py                     ← كيانات + قيود سكيمة (المادة ٣-٣)، بلا منطق أعمال
```

- view أو serializer أو مهمة Celery تكتب في قاعدة البيانات مباشرة = PR مرفوض.
- كل خدمة: دالة صريحة المدخلات، ترجع كياناً أو ترفع استثناء مسمّى — لا أعلام
  نجاح/فشل.
- الدفتر تحديداً: لا شيء يكتب فيه إلا `apps.money.services.post` (المادة ١-٢).

### التطبيق — ثلاث طبقات

```
presentation/   شاشات وwidgets وcontrollers (Riverpod)
domain/         كيانات وusecases — Dart صافٍ بلا Flutter ولا dio
data/           repositories + العميل المولَّد + التخزين المحلي
```

- `presentation` لا تستورد `data` أبداً — عبر `domain` فقط.
- كل مبلغ مالي يصل نصاً عشرياً ويُعرض كما وصل (المادتان ١-٦ و٣-٢) — ممنوع
  `double` للفلوس في Dart أيضاً.

### ويب العميل — ثلاث طبقات

```
app/            الصفحات والتوجيه (App Router)
features/       منطق العرض لكل مجال
lib/api/        العميل المولَّد من المخطط
```

- `features` لا تستورد `lib/api` إلا عبر واجهة واحدة.
- **لا قاعدة عمل في الويب**: لا حساب سعر، ولا شرط أهلية، ولا قرار «يقدر يزايد
  ولا لأ». الخادم يقرّر والواجهة تعرض (المادة ٤-٥).
- ممنوع `Number(` أو `parseFloat(` على أي مبلغ — `0.1 + 0.2` في جافاسكربت ليس
  `0.3` أيضاً. فحص نصّي في CI، نظير T122.

## 6. ميثاق الكود النظيف — شروط الدمج

كل PR يُحاسَب على هذه، والمراجعة **متقاطعة**: م1 يراجع م2، م2 يراجع م3، م3
يراجع م1. ما يمسّ `apps/money` يراجعه م1 وجوباً مهما كان كاتبه.

1. **فرع لكل تاسك** باسمه: `002/T105-lock-ordering`. لا فرع يعيش أكثر من أسبوع.
2. **Conventional commits**: `feat(money): ...` · `fix(bidding): ...` · `test:` · `refactor:`.
3. **PR صغير**: هدفه ≤ 400 سطر تغيير. أكبر من ذلك يُقسَّم.
4. **لا دمج** إلا بـ: CI أخضر + مراجعة معتمدة + تاسك محدَّث الحالة في `tasks.md`.
5. **اختبار يفشل بدون التغيير** مع كل سلوك جديد (المادة ٤-١). خدمات المال:
   تغطية فروع كاملة.
6. **type hints** في كل دالة جديدة؛ mypy strict على `apps/money` لا يُستثنى.
7. **الأسماء** إنجليزية في الكود، عربية في كل ما يراه المستخدم (المادة ٤-٣)،
   ورسائل الأخطاء الموجهة للمستخدم عربية مفهومة.
8. **التعليقات تشرح السبب لا الفعل** (المادة ٤-٦)، والدوال قصيرة ذات مسؤولية
   واحدة — دالة تحتاج «و» لوصفها تُقسَّم.
9. **لا تكرار لنقطة قرار** (المادة ٤-٥): الأهلية والتسعير والرصيد يُسألون في
   مكان واحد ويُستدعى.
10. **لا TODO يُدمج**: إما تاسك في `tasks.md` أو يُحل الآن.

## 7. إيقاع العمل

- **يومياً:** standup قصير (مكتوب يكفي): أمس/اليوم/معطِّل. المعطِّلات العابرة
  للمسارات تُحل في نفس اليوم.
- **أسبوعياً:** مراجعة تقدم على `tasks.md` مع تحديث الحالات (⬜/🟡/✅)، ونظرة
  على نقاط التزامن القادمة.
- **عند إغلاق كل فيز:** المرور على بوابة الإغلاق الخمسية بنداً بنداً، وكاتب
  الفيز يحدّث `spec.md` بما تغيّر فعلاً.
- **plan.md لكل فيز** يكتبه مالكه عند بدء الفيز (اصطلاح المستودع)، ويأخذ قرارات
  التقنية من هذه الوثيقة كافتراض — أي خروج عنها يُذكر سببه في نفس الملف.
